# 空格接受建议词和联想词

关联 issue：#2

## 为什么

空格是打英文时最顺手的键，现在却用不上候选：组词时空格永远提交原样，拼错的 helo 按空格还是 helo；联想时按空格直接收起联想。要用建议词和联想词只能按 Tab 或数字键，和手机键盘、中文输入法的习惯都不一样，维护者实际用下来觉得不友好。

## 做什么

- 新增设置「空格接受建议」，默认开启。
- 开启时，组词的原样不是已知词、并且拼写检查给出了纠错时，高亮一开始就落在第一个纠错词上；空格照旧提交高亮项，于是空格提交的是纠错词。
- 开启时，联想状态下（刚提交完一个词并带了空格）再按空格，接受高亮的联想词加空格，并继续联想；没有联想词时空格照常交给应用。
- 关闭时保持现有行为：空格提交原样，联想时空格收起联想并交给应用。

## 不做什么

- 不在空格时自动补全：原样不是已知词、但只有补全（tomo → tomorrow）没有纠错时，高亮仍在原样上，补全照旧用 Tab 或数字键。
- 不做「刚自动纠错后按退格还原」：要改已上屏的文字，不同应用对替换范围的支持不一致，另议。
- 不改 Tab、⇧Tab、数字、回车、Esc 的语义。

## 涉及的能力

- 修改：`composition`（空格与初始高亮）、`prediction`（联想时空格）、`settings`（新开关）

## 影响

- Core：`Preferences` 新增一项并持久化；`InputSession` 的初始高亮与联想状态下的空格。
- App：设置窗新增一个开关。
- 不改数据文件格式，不改 Info.plist。升级后需要重新 `make install`。
- README 按键表、bootstrap 设计里「空格默认提交原样」的说明要同步。

## 成功标准

- 开关开启时：helo 按空格得到 "hello "；help 按空格得到 "help "；联想中按空格接受高亮联想词并继续联想。
- 开关关闭时：现有空格相关场景全部照旧通过。
- `make test` 全绿；真机上在备忘录、浏览器里各打一段验证。
