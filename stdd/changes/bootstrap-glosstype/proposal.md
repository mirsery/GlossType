# 从零实现 GlossType 输入法

## 为什么

用英文写东西时想随手确认用词和整句意思：现有的英文输入法只给补全和下一个词，不给中文；开翻译软件来回切换又打断输入。维护者希望有一个自己能掌控、可以开源的输入法：打字时候选词旁边就有中文释义，候选窗底部实时显示整句的中文翻译，并能联想下一个词和短语。

参考了 mgxv/SwiftType 的交互思路（光标下方悬浮候选条、补全 / 纠错 / 下一个词联想）。该仓库没有许可证，本项目不使用它的任何代码和数据，全部自行实现。

## 做什么

- 输入法本体（InputMethodKit）：字母组词显示为标记文本，空格 / 数字 / Tab / 回车 / Esc / 标点 / 方向键有明确语义，切走应用时不丢字。
- 候选：原样 + 补全 + 拼写纠错，按「上下文语言模型 → 用户习惯 → 词频词表 → 系统拼写检查」合并排序，大小写跟随输入。
- 每个候选词下方显示简短中文释义（ECDICT，离线，变形词回落到原形）。
- 候选窗底部显示「当前这句 + 正在输入的词」的中文翻译：苹果本地翻译，防抖，只认最新结果，带缓存；语言包没装时提示去设置窗下载。
- 联想：提交一个词后给出下一个词候选和一条短语；Tab 接受下一个词并可连续接，⇧Tab 接受整条短语。
- 语言模型可插拔：定义 n-gram SQLite 格式和读取实现，提供从任意语料（一行一句）生成该格式的脚本；不内置语料。用户自备的模型放到固定位置即覆盖内置模型。
- 本地学习：记录用户提交的词和前两个词的搭配，提高常用搭配的排序；可关闭、可一键清除。
- 候选窗：光标下方，空间不够翻到上方，左右不出屏；跟随浅色 / 深色模式。
- 设置窗：释义、整句翻译、短语联想、学习开关，候选数量，翻译延迟，语言包状态与下载，清除学习记录。
- 构建与安装：`make app` 组装 `.app`，`make install` 安装并注册启用输入源；`make data` 生成词典数据。
- STDD 基础设施：流程文档、模板、追溯检查脚本。

## 不做什么

- 不内置任何语言模型语料，也不训练模型（维护者另定，要日常会话风格）。
- 不接云端翻译或大模型（以后可以在翻译接口上加实现）。
- 不做退格回到已提交的词重新组词。
- 不做多语言（只做英文输入、中文释义与翻译）。
- 不做候选多行网格、主题配色自定义、按应用切换输入源。
- 不做安装包（pkg）、公证和自动更新。
- 本次不在维护者本机编译 app、不装 Xcode；app 的编译与测试由维护者在另一台 macOS 15+ 的机器上完成。

## 涉及的能力

- 新增：`composition`、`completion`、`prediction`、`gloss`、`translation`、`learning`、`panel`、`settings`、`install`、`dictdata`、`lmdata`

## 影响

- 新仓库，无存量用户。
- 数据文件：`glossary.sqlite`（释义 + 词频）、`ngram.sqlite`（语言模型，可选）、`user-history.sqlite`（学习记录，在 `~/Library/Application Support/GlossType/`）。格式见 `docs/data-formats.md`。
- 安装后需要在「系统设置 → 键盘 → 输入法」里添加 GlossType（`make install` 会尝试自动注册并启用）。

## 成功标准

1. `make test` 在 macOS 15+、Xcode 16+ 的机器上全绿，`make stdd-check` 无报错。
2. `make data && make app && make install` 后，GlossType 出现在输入源里，能在「文本编辑」里正常打英文。
3. 输入时候选窗出现在光标下方，候选带中文释义；底部显示整句中文翻译（语言包已装时）。
4. 用 `make lm` 生成的语言模型放到位后，提交一个词能看到下一个词和短语联想，Tab / ⇧Tab 能接受。
5. 关掉学习后不再写学习记录；清除后记录为空。
